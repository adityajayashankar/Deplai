# DEPLAI — Deployment Execution Hardening & End-to-End Reliability

You are continuing work on the existing Deplai codebase.

A Deployment Execution Engine has already been implemented for:

```text
AWS EC2
+
Docker
+
Amazon ECR
+
AWS Systems Manager (SSM)
```

The current implementation already includes:

* Deployment Contract
* Deployment Blueprint
* allowlisted deployment operations
* SSM execution adapter
* SSH disabled by default
* fake adapter for tests
* environment locking
* retry classification
* secret redaction
* rollback to previous immutable digest
* preflight
* deployment APIs
* deployment UI/timeline
* ECR artifact validation
* Docker/SSM host setup
* deployment state handling
* initial tests

Do NOT rebuild this system.

Your job is to **audit, harden, test, and improve the existing implementation so that a real production deployment can survive failure, restart, retry, rollback, and concurrency safely.**

The objective is to turn the existing v1 implementation into a reliable production deployment subsystem.

# 3. HARD REQUIREMENT — IMMUTABLE DEPLOYMENT SNAPSHOT

Once execution begins:

```text
Deployment Contract
        ↓
Deployment Blueprint
        ↓
Immutable Execution Snapshot
```

must be created.

Persist:

```text
deployment_id
contract_version
blueprint_version
blueprint_hash
source_commit
artifact_id
image
digest
target
environment
strategy
timestamp
```

After execution begins, UI or agents must not mutate the active deployment blueprint.

Every step/event must reference the immutable snapshot.

This ensures we can prove:

> Exactly what was approved and exactly what was executed.

# 4. ARTIFACT INTEGRITY

Harden artifact validation.

The deployment must verify:

```text
project
artifact
registry
repository
image
digest
artifact status
```

Artifact must be:

```text
VERIFIED
```

or:

```text
PROMOTED
```

according to the existing Deplai artifact lifecycle.

The executor must never deploy an arbitrary tag without verifying its immutable digest.

Required lifecycle:

```text
Requested artifact
      ↓
Resolve digest
      ↓
Compare with approved digest
      ↓
PASS
      ↓
Pull image
      ↓
Inspect actual image digest
      ↓
Compare again
      ↓
PASS
      ↓
Start application
```

If any digest mismatch occurs:

```text
ARTIFACT_INTEGRITY_FAILED
```

and deployment must stop.

# 5. ENVIRONMENT ABSTRACTION

Ensure the deployment operates against:

```text
Project
   ↓
Environment
   ↓
Target
```

rather than using raw EC2 IDs as the primary product abstraction.

For example:

```text
Project
 ├── Development
 ├── Staging
 └── Production
```

Each environment resolves its active deployment target.

The EC2 instance is an implementation detail.

The user-facing deployment operation should conceptually be:

```text
Deploy artifact X
to environment Y
```

not:

```text
Run deployment on EC2 instance Z
```

# 7. ENVIRONMENT LOCKING

Audit the existing lock implementation.

Guarantee:

```text
At most one active deployment
per environment
```

unless an explicitly supported deployment strategy permits otherwise.

Test:

```text
Deployment A
    ↓
RUNNING

Deployment B
    ↓
QUEUED / REJECTED
```

Prevent:

```text
deployment A modifies environment
deployment B modifies same environment simultaneously
```

The lock must survive:

```text
worker crash
process restart
timeout
deployment failure
rollback
```

Avoid stale locks.

Implement safe lease/heartbeat behavior if the existing architecture requires it.
